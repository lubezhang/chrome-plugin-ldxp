# 链动小铺助手设计文档

> 文档状态：基于 `manifest.json` 版本 `1.1.0` 与当前工作区源码整理。
> 适用读者：维护扩展功能、排查站点兼容性问题或准备发布的开发者。
> 运行平台：Chrome 102 及以上，Manifest V3。

## 1. 文档范围

链动小铺助手是一个只作用于 `wzyp.cn` 及其子域的 Chrome 扩展。它提供三组能力：

1. 在指定小铺页重排商品、隐藏缺货商品并调整商品布局。
2. 查询订单、筛选订单、读取和复制卡密。
3. 保存订单联系方式与安全密码，并在订单确认弹窗出现时自动填入空字段。

本文描述当前实现的系统边界、运行时组件、数据流、消息协议、站点接口、存储策略、界面状态和主要取舍。安装与使用步骤见项目根目录的 [README](../README.md)，视觉稿源文件见 [ldxp-plugin.pen](design/ldxp-plugin.pen)。

## 2. 设计目标与约束

### 2.1 设计目标

- 不修改 WZYP 服务端，通过内容脚本复用当前页面的同源环境和登录状态。
- 商品整理失败时不阻断原站页面；接口不可用时仍保留基于 DOM 的缺货识别。
- 默认缩短敏感数据生命周期：验证码票据和未勾选“长期记住”的安全密码只保存到浏览器会话。
- 不覆盖用户已经在订单确认弹窗中输入的值。
- 在窄小的扩展弹窗中完成配置、验证、查询、筛选和卡密操作。
- 不引入构建期框架或第三方运行时依赖，安装包由静态文件直接组成。

### 2.2 明确约束

- 商品整理只支持精确路径 `/shop/2VWX76A4`。
- 库存接口固定查询分类 `67214`、商品类型 `card`，单次最多读取 100 条。
- 订单列表一次最多汇总 50 页，每页 100 条，即最多 5,000 条。
- 页面结构、CSS 类名和 WZYP 私有接口均不受本项目控制，兼容性依赖运行时容错。
- 项目当前没有自动化测试、包管理器或编译步骤。

## 3. 系统上下文

扩展由三个彼此隔离的运行时上下文组成。

```text
┌──────────────────────── Chrome 扩展 ────────────────────────┐
│                                                             │
│  popup.html + popup.js                                      │
│  配置、订单列表、筛选、分页、卡密展示                        │
│          │ chrome.tabs.sendMessage                          │
│          ▼                                                  │
│  content.js（注入 wzyp.cn 页面）                            │
│  DOM 整理、自动填充、同源 API 请求、人机验证签名             │
│          │ chrome.runtime.sendMessage                       │
│          ▼                                                  │
│  background.js（MV3 Service Worker）                        │
│  代理访问 chrome.storage.session 中的票据和密码              │
│                                                             │
└─────────────────────────────────────────────────────────────┘
           │ fetch，same-origin 或 credentials: omit
           ▼
┌────────────────────── WZYP 页面与接口 ──────────────────────┐
│ 商品 DOM、订单确认弹窗、商品/订单/验证码接口                 │
└─────────────────────────────────────────────────────────────┘
```

内容脚本承担站点适配层。订单请求没有放在弹窗或后台脚本中，因为内容脚本运行在目标页面上下文附近，可以使用相对 URL，并通过 `credentials: "same-origin"` 复用站点会话。后台 Service Worker 不处理业务接口，只负责内容脚本不能直接可靠访问的会话存储。

## 5. 运行时职责

### 5.1 弹窗

弹窗是用户操作入口，但不直接访问 WZYP 接口。初始化过程如下：

1. 并行读取商品设置和订单设置。
2. 查询当前窗口的活动标签页。
3. 校验 URL 是否属于 `wzyp.cn` 或其子域。
4. 若当前路径为 `/order`，默认打开订单查询；其他 WZYP 页面默认打开商品整理。
5. 通过标签页消息委托内容脚本读取或修改页面状态。

弹窗关闭后，内存中的订单列表和已读取卡密随之销毁。再次打开会重新建立 UI 状态，但本地或会话存储中的配置仍然存在。

### 5.2 内容脚本

内容脚本在所有匹配的 WZYP 页面于 `document_idle` 注入。启动时会：

- 从本地存储读取商品排序和缺货过滤设置。
- 在目标小铺页注入商品布局与图片隐藏样式。
- 扫描并处理现有商品节点。
- 注册 `MutationObserver`，处理站点后续异步渲染的商品和订单确认弹窗。
- 注册消息监听器，为弹窗提供页面操作与接口代理。
- 监听本地存储变化，使已经打开的页面无需刷新即可应用新设置。

内容脚本还保留了页面分析和元素拾取相关消息处理器，但当前弹窗没有暴露对应入口。它们属于未被当前产品界面使用的内部兼容表面。

### 5.3 后台 Service Worker

后台脚本仅处理四类会话存储消息：读取会话密码、读取票据、写入票据和清除票据。处理器对异步分支返回 `true`，保证 `sendResponse` 通道在 Promise 完成前保持有效。

将票据放在后台会话存储中有两个目的：

- 内容脚本不直接持有 `chrome.storage.session` 的访问策略。
- 票据在页面跳转和弹窗关闭后仍可复用，但在浏览器会话结束后自动清除。

## 6. 核心业务流程

### 6.1 商品整理

商品整理使用“DOM 识别 + 库存接口”两条信号源。

```text
加载设置
   │
   ├─ 注入目标店铺网格布局和图片隐藏样式
   │
   ├─ DOM 扫描：识别“缺货 / 售罄 / 无货 / 已下架”或 .stock.rank0
   │      └─ 找到商品容器并记录原 display 样式后隐藏
   │
   ├─ 库存接口：读取 stock_count === 0 的 goods_key / 商品名
   │      └─ 用商品链接或规范化商品名补充隐藏
   │
   └─ 按价格或原始顺序重新 append 商品节点
```

排序算法按商品父容器分组，只在同一容器内重排。首次遇到卡片时记录其原始索引；价格相同时以原始索引作为稳定排序条件。价格无法解析的商品排在可解析价格之后。选择“网站默认顺序”时按已记录的原始索引恢复。

隐藏商品前会保存其内联 `display` 值与优先级。关闭过滤时恢复原值，而不是统一写成某个显示模式。CSS `:has()` 规则覆盖首屏缺货卡片，DOM 扫描和观察器负责兼容更多结构与动态节点。

### 6.2 订单查询与人机验证

```text
用户进入订单页签
   │
   ├─ 未配置联系方式 ──────────────► 引导打开配置
   │
   └─ 已配置联系方式
          │
          ├─ 无有效 ticket ─────────► 获取验证码
          │                              │
          │                              ├─ 用户输入验证码
          │                              ├─ 计算接口要求的 MD5 签名
          │                              └─ 保存 ticket 到会话存储
          │
          └─ POST /shopApi/Order/list
                 │
                 ├─ 验证失效 ─────────► 清票据并重新验证
                 ├─ 请求失败 ─────────► 展示重试状态
                 └─ 成功
                        ├─ 四页一批并发补齐订单，最多 50 页
                        ├─ 在弹窗内按名称/订单号和状态筛选
                        └─ 每 10 条进行客户端分页
```

验证码签名为 `MD5(MD5(code + ip) + "JING")`。这里的 MD5 是对站点协议的兼容实现，不承担密码哈希或安全存储职责。

订单列表第一次请求 100 条，并根据返回的 `total` 计算后续页数。后续请求按四页一组并发执行。任何一页返回验证失效时，整个加载过程转回验证状态；其他错误会进入可重试状态。

### 6.3 卡密读取

用户点击某个订单的“读取卡密”后，弹窗把订单号和当前安全密码发送给内容脚本。内容脚本先校验订单号只能包含字母、数字、下划线和连字符，再请求订单详情。

只有接口返回成功且订单状态为 `1` 时才展示卡密。卡密进入弹窗后默认以 `************` 遮罩，用户可以单条或批量显示、隐藏、复制。遮罩只减少旁观泄露，真实卡密仍存在于弹窗页面的 JavaScript 内存中，直到弹窗关闭。

### 6.4 订单确认自动填充

内容脚本持续观察页面新增节点，并寻找可见且文本包含“订单确认”的对话框。它按输入框的 `placeholder`、`name`、`id` 和 `className` 查找“联系方式”和“安全密码”。

写值时调用 `HTMLInputElement.prototype.value` 的原生 setter，并派发冒泡的 `input` 和 `change` 事件，以兼容受控表单。以下任一条件成立时不会写入：

- 输入框不存在。
- 输入框已有值。
- 对应配置为空。

因此自动填充不会覆盖用户手动输入的内容。设置变化后，弹窗会发送刷新消息；内容脚本也会监听本地存储变化并清除配置缓存。

## 7. 数据与存储设计

### 7.1 存储键

| 存储区 | 键 | 类型 / 默认值 | 用途 |
| --- | --- | --- | --- |
| `chrome.storage.local` | `hideSoldOutProducts` | `boolean` / `true` | 是否隐藏缺货商品。 |
| `chrome.storage.local` | `productSortMode` | `"default" \| "price-asc" \| "price-desc"` / `"price-asc"` | 商品排序方式。 |
| `chrome.storage.local` | `orderContact` | `string` / `""` | 订单查询和自动填充使用的联系方式。 |
| `chrome.storage.local` | `rememberOrderPassword` | `boolean` | 是否把安全密码长期保存在本地。 |
| `chrome.storage.local` | `orderPassword` | `string` / 不存在 | 仅在长期记住密码时保存，内容为明文。 |
| `chrome.storage.session` | `sessionOrderPassword` | `string` / `""` | 未长期记住时的会话级安全密码。 |
| `chrome.storage.session` | `sessionOrderVerificationTicket` | `string` / `""` | 订单查询的人机验证票据。 |

旧版本可能在本地存储保留 `wzypOrderVerificationTicket`。内容脚本首次读取时会尝试把它迁移到会话存储，成功后删除旧键。若旧版本已有 `orderPassword` 但没有 `rememberOrderPassword`，弹窗会把它解释为用户选择长期保存，并补写该偏好。

### 7.2 敏感数据生命周期

| 数据 | 默认生命周期 | 可选生命周期 | 发送位置 |
| --- | --- | --- | --- |
| 联系方式 | 持久本地存储 | 无 | 订单列表接口、订单确认表单。 |
| 安全密码 | 浏览器会话 | 用户可选择持久本地存储 | 订单详情接口、订单确认表单。 |
| 验证票据 | 浏览器会话 | 无 | 订单列表接口。 |
| 卡密 | 当前弹窗内存 | 无 | 仅显示或写入系统剪贴板。 |

扩展没有自建远程服务，也不会把上述数据写入安装包。长期保存的安全密码没有加密，安全性依赖 Chrome 用户配置与设备访问控制。

## 8. 消息协议

### 8.1 弹窗到内容脚本

当前弹窗使用以下消息：

| `type` | 主要请求字段 | 主要响应字段 | 异步 |
| --- | --- | --- | --- |
| `get-product-state` | 无 | `supported`, `hidden`, `total`, `filterEnabled`, `sortMode` | 否 |
| `set-product-filter` | `enabled` | 商品状态对象 | 否 |
| `set-product-sort` | `mode` | 商品状态对象 | 否 |
| `get-order-info` | `contact`, `page`, `pageSize` | `orders`, `total`, `requiresVerification` 或 `error` | 是 |
| `get-order-cards` | `tradeNo`, `password` | `cards` 或 `error` | 是 |
| `start-order-captcha` | 无 | `imageUrl` 或 `error` | 是 |
| `verify-order-captcha` | `code` | `verified`, `imageUrl?`, `error?` | 是 |
| `refresh-order-autofill` | 无 | `refreshed` | 否 |

内容脚本还支持 `analyze-page`、`get-account-info`、`start-picker`、`get-selected-element`、`hide-sold-out-products`、`restore-sold-out-products`、`update-selected-element` 和 `restore-selected-element`。它们当前没有弹窗调用方，修改或删除前应先确认是否有外部调试流程依赖。

### 8.2 内容脚本到后台

| `type` | 请求字段 | 响应字段 |
| --- | --- | --- |
| `get-session-order-password` | 无 | `password` |
| `get-session-order-ticket` | 无 | `ticket` |
| `set-session-order-ticket` | `ticket` | `saved` |
| `clear-session-order-ticket` | 无 | `cleared` |

消息协议目前没有独立 schema，也没有检查 `sender` 来源。新增消息时应同时更新发送方、接收方、错误响应和本文档，避免弹窗永久停留在加载状态。

## 9. WZYP 接口契约

这些接口均由 `src/content.js` 调用，契约来自当前代码观察，并非 WZYP 的公开稳定 API。

| 目的 | 方法与路径 | 请求体重点 | 成功条件 |
| --- | --- | --- | --- |
| 商品库存 | `POST /shopApi/Shop/goodsList` | 固定店铺 token、分类、`goods_type: "card"`、`pageSize: 100` | `code === 1` 且 `data.list` 为数组。 |
| 订单列表 | `POST /shopApi/Order/list` | `current`, `pageSize`, `keywords`, `ticket` | `code === 1`；读取 `data.list` 与 `data.total`。 |
| 订单详情 | `POST /shopApi/Order/info` | `trade_no`, `query_password`, `dump: 1` | `code === 1`、`data.status === 1`；读取 `response.cards`。 |
| 获取验证码 | `POST /shopApi/Common/captchaStart` | `{ "code": "" }` | 返回 `img_url`, `check_url`, `ip`。 |
| 校验验证码 | `POST <check_url>` | `code`, `sign` | `code === 1` 且返回 `data.ticket`。 |

订单和验证码请求使用 `credentials: "same-origin"`。商品库存请求使用 `credentials: "omit"`，表明该数据按当前设计不依赖登录态。HTTP 401/403 或包含“人机、验证码、ticket、captcha”等文本的业务错误会使已保存票据失效。

## 10. 界面与状态设计

### 10.1 信息架构

弹窗由固定头部、双页签和一个可滚动内容区组成：

- “商品整理”页签包含排序、缺货开关和折叠的订单自动填写配置。
- “订单查询”页签包含订单概览、刷新、搜索、状态筛选、结果列表、分页、人机验证与错误恢复。
- 非 WZYP 页面仅显示提示，不初始化站点相关能力。

订单视图使用显式状态切换，而不是路由：未配置、加载中、需验证、验证中、加载成功、空结果、筛选为空和请求失败。加载时渲染三条骨架卡片；错误状态提供重试或配置入口。

### 10.2 可访问性

- 页签使用 `tablist`、`tab`、`tabpanel`、`aria-selected` 和左右方向键切换。
- 图标按钮提供 `title` 与 `aria-label`。
- 异步反馈使用 `role="status"` 或 `aria-live="polite"`。
- 表单错误通过 `aria-invalid` 标记。
- 所有交互控件有 `:focus-visible` 样式。
- `prefers-reduced-motion` 下缩短动画并限制重复次数。

### 10.3 视觉来源

运行时样式以 `tokens.css` 和 `src/popup.css` 为准。`ldxp-plugin.pen` 包含设计系统、商品整理、自动填写配置、订单验证、订单列表与卡密五个画板，可用于后续视觉迭代。

当前 `.pen` 文件的命名颜色值与 `tokens.css` 中的 OKLCH 令牌并不完全一致，特别是强调色方向不同。因此它是设计参考，不是可直接生成运行时样式的单一事实源。若后续要求像素级一致，应先决定以视觉稿还是运行时代码为基准，再同步另一侧。

## 11. 容错与降级

- 库存接口失败：保留 DOM 缺货识别、CSS 过滤和排序能力。
- 页面异步更新：`MutationObserver` 在动画帧中合并重复处理，避免每次 DOM 变化立即执行完整扫描。
- 票据过期：清除会话票据和旧版本地票据，返回人机验证流程。
- 卡密读取失败：保留订单卡片，提供局部重试，不重新加载全部订单。
- 剪贴板 API 不可用：回退到隐藏 `textarea` 与 `document.execCommand("copy")`。
- 内容脚本无法通信：弹窗显示刷新页面或重试提示。
- 自动填充结构失配：捕获错误且不影响站点原流程。

## 12. 安全与隐私边界

### 12.1 已有保护

- 主机权限限制在 `wzyp.cn` 及其子域。
- 扩展页 CSP 只允许自身脚本，图片额外允许 `data:` 和 `https://wzyp.cn`。
- 订单详情页 URL 固定为 `https://wzyp.cn/order/result/`，订单号经过 `encodeURIComponent`。
- 卡密默认遮罩，订单号在请求前进行字符白名单校验。
- 自动填充只写空输入框。
- 默认不长期保存安全密码和验证票据。

### 12.2 仍需接受或改进的风险

- “长期记住”会把安全密码以明文保存到 `chrome.storage.local`。
- 内容脚本依赖私有接口、硬编码店铺和站点 DOM，站点改版可能静默降低功能。
- 消息处理器没有校验 `sender`，也没有对所有请求字段做统一 schema 校验。
- 商品和订单确认各有一个覆盖 `document.body` 子树的观察器，站点高频更新时可能产生扫描成本。
- 卡密复制后进入系统剪贴板，生命周期超出扩展控制。
- 自实现 MD5 需要用协议样例或已知向量持续验证，避免兼容性回归。

## 13. 构建与发布

项目没有依赖安装或编译阶段。开发时可直接在 `chrome://extensions` 加载项目根目录。发布脚本要求系统已安装 `node`、`zip` 和 `unzip`，并执行以下动作：

1. 解析并校验 `manifest.json`。
2. 读取版本号和 128 px 图标路径。
3. 确认图标存在。
4. 把 `manifest.json`、`popup.html`、`tokens.css`、`src/` 和 `assets/` 打入 ZIP。
5. 通过 `unzip -t` 验证压缩包。

产物路径为 `dist/linked-shop-helper-<version>.zip`。发布前必须先提升 `manifest.json` 中的版本号。

## 14. 验证策略

当前仓库没有自动化测试，至少应执行以下发布前检查：

```sh
node --check src/background.js
node --check src/content.js
node --check src/popup.js
./scripts/build.sh
```

手工回归应覆盖：

1. 非 WZYP 页面显示不支持提示。
2. 目标小铺页的三种排序、缺货开关、动态加载商品和设置持久化。
3. 联系方式必填、密码会话保存、密码长期保存及两种模式互相切换。
4. 订单确认弹窗自动填充、已有输入不被覆盖。
5. 首次验证、错误验证码、票据复用、票据过期。
6. 订单全量加载、搜索、四种状态筛选、分页与刷新。
7. 卡密读取失败、单条/批量显示、复制与重试。
8. 键盘页签切换、焦点可见性与减弱动效设置。

后续若增加自动化测试，优先把纯函数和协议逻辑从 DOM 代码中拆出，覆盖排序稳定性、状态映射、分页上限、票据失效识别和 MD5 已知向量；再用浏览器测试覆盖消息链路和站点 DOM 适配。

## 15. 变更指南

### 新增站点页面能力

1. 在 `content.js` 中实现站点读取或修改逻辑。
2. 增加具名消息并定义稳定的成功、失败响应。
3. 在 `popup.js` 中只维护界面状态，不直接复制站点适配代码。
4. 核对 `manifest.json` 的主机权限和 CSP 是否仍为最小范围。
5. 更新消息协议、容错策略和手工回归项。

### 修改存储策略

1. 明确数据是否敏感、是否需要跨浏览器会话存在。
2. 为旧键提供一次性迁移和成功后清理。
3. 同步弹窗、内容脚本和后台脚本的读取路径。
4. 验证从旧版本升级、切换偏好以及清空数据三条路径。

### 适配 WZYP 改版

优先维持接口与 DOM 双路径。修改选择器时，应在真实页面验证首屏、异步加载、移动宽度和订单确认弹窗；修改接口时，应同时验证 HTTP 错误、业务错误、空数据和验证过期，不能只验证成功响应。

## 16. 当前技术债务与演进顺序

建议按以下顺序处理后续工程化工作：

1. 为消息请求、响应和 WZYP 接口响应增加运行时校验，先消除静默结构漂移。
2. 为排序、分页、状态映射、验证码签名和迁移规则增加单元测试。
3. 把商品、订单、自动填充和遗留元素拾取逻辑拆成独立模块，降低 `content.js` 的变更耦合。
4. 对两个 `MutationObserver` 增加作用域收窄或性能观测，确认真实站点上的扫描成本。
5. 清点当前未使用的页面分析与元素拾取消息，确认无外部依赖后删除或正式文档化。
6. 统一 `.pen` 视觉令牌与运行时 CSS 令牌，明确唯一视觉事实源。
